# 캐모임 — 한인 업체 지도 기획서

작성일: 2026-07-08

## 1. 개요

캐나다 거주 한인(유학생·이민자·워홀러)이 주변의 한인 업체를 쉽게 찾을 수 있도록 캐모임 앱 안에 지도 기반 탐색 기능을 추가한다. 식당뿐 아니라 카페·베이커리, 마트, 미용실, 병원/한의원, 부동산·이민 서비스 등 한인 업체 전반을 다룬다.

## 2. 범위

- **업체 카테고리**: 음식점, 카페/베이커리, 마트, 미용실, 병원/한의원, 부동산·이민 서비스, 기타
- **출시 지역**: 유학생·한인 밀집 대도시(토론토, 밴쿠버, 몬트리올)부터 시작 후 순차 확장
- **MVP 범위**: 지도/리스트 탐색, 업체 상세, 즐겨찾기, 유저 제보, 신고. 리뷰·별점 시스템은 2차 이터레이션으로 보류

## 3. 데이터 확보 전략

세 가지 소스를 조합한다.

1. **Google Places API 자동수집**: 도시별로 "한식당", "한인마트", "한인미용실" 등 키워드로 검색해 초기 데이터를 확보한다. `source: google`, `status: approved`로 시드하며, University 모델의 `seedUniversities` 스크립트 패턴을 재사용한다.
2. **관리자 수동 입력**: Admin 화면에 CRUD를 추가해 운영진이 직접 등록/수정한다.
3. **유저 제보 + 승인**: 앱 내 "업체 추가 제안" 버튼으로 사용자가 제보하면 `status: pending`으로 들어가고, 관리자가 승인/거절한다. Group의 `pending_review` 흐름을 재사용한다.

## 4. 데이터 모델 (`server/models/Business.js`)

| 필드 | 타입 | 설명 |
|---|---|---|
| name | String | 업체명 |
| category | String (enum) | 음식점/카페/마트/미용실/병원/부동산이민/기타 |
| city | String | 도시 (필터링 기준) |
| address | String | 전체 주소 |
| location | GeoJSON Point | `{ type: 'Point', coordinates: [lng, lat] }`, 2dsphere 인덱스 |
| phone | String | 연락처 (선택) |
| hours | String | 영업시간 (선택) |
| images | [String] | Cloudinary URL, 폴더: `camoim/businesses` |
| source | String (enum) | `google` \| `admin` \| `user` |
| status | String (enum) | `pending` \| `approved` \| `rejected` |
| submittedBy | ObjectId (User) | 유저 제보 시 작성자 |
| bookmarkCount | Number | 즐겨찾기 수 (선택, 정렬용) |

기존 `Bookmark` 모델을 그대로 재사용해 업체 즐겨찾기를 지원하고, `Report` 모델을 재사용해 폐업·오정보 신고를 처리한다.

## 5. 화면 구성 (프론트엔드)

- **지도 메인 화면**: 상단 도시 선택 드롭다운, 카테고리 필터 칩, 지도 위 카테고리별 핀(클러스터링 포함), 하단 리스트/지도 토글, "내 주변" 버튼
- **업체 상세 화면**: 대표 사진, 업체명, 카테고리 뱃지, 주소, 전화번호, 영업시간, 즐겨찾기 버튼, 길찾기 버튼(지도 앱 딥링크), 신고 버튼
- **업체 제보 화면**: 업체명/카테고리/주소/사진/전화번호 입력 폼, 제출 버튼
- **관리자 화면**: 업체 목록(승인 대기 큐 포함), 등록/수정/삭제, 제보 승인·거절

신규 라이브러리: `react-native-maps`, 위치 권한을 위한 `expo-location`.

## 6. 백엔드 API 개요

- `GET /api/businesses?city=&category=&near=lng,lat` — 목록 조회 (지오스페이셜 `$near` 쿼리)
- `GET /api/businesses/:id` — 상세 조회
- `POST /api/businesses` — 유저 제보 (status: pending)
- `PUT /api/admin/businesses/:id` — 관리자 수정/승인/거절
- `DELETE /api/admin/businesses/:id` — 관리자 삭제
- `POST /api/businesses/:id/report` — 신고 (기존 Report 라우트 재사용)

## 7. QA 체크포인트

- 폐업/오정보 신고 처리 흐름 검증
- 위치 권한 거부 시 도시 수동 선택 fallback
- 유저 제보 스팸 방지 (승인 큐, 중복 등록 감지)
- Google Places 데이터 이용약관·저작권 확인
- 지도 핀이 많아질 때 성능(클러스터링) 검증

## 8. 단계별 로드맵

- **1단계**: Business 모델·API·admin CRUD 구축, Google Places로 토론토/밴쿠버/몬트리올 초기 데이터 시드
- **2단계**: 지도/리스트 프론트 화면, 즐겨찾기 연동
- **3단계**: 유저 제보 기능 오픈
- **4단계**: 도시 확장, 리뷰/별점 기능 검토
